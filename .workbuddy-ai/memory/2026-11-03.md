## Product dataset + photo integrity (duplicates and label mismatch)

**Dataset** — `backend/app/dataset/`: 51 products, 6 verticals (vehicles 10, farming 9,
food 9, parts 7, building 8, electronics 8), 17 categories, 5.3 MB of images.
Built by `backend/scripts/build_dataset.py`, which pulls each product's lead photo from
its Wikipedia article (so the label is ground truth), downscales to 900px, and stores a
64-bit dHash. Wikimedia only pre-renders a few widths, so the script downloads the
original from `upload.wikimedia.org` and resizes locally. Two articles had no lead image
(Urea, Chambo) and were dropped; six others had blank/diagram leads and were replaced
(Tesla Model Y, Pesticide application, Engine-generator, Television, Clothes iron) or
removed (Alternator). Every photo was visually checked against its label in contact sheets.

**Schema** — `products` (metadata + `photo_file`, `photo_hash`, `photo_sha1`, `photo_source`)
and new listing columns `model`, `photo_hash`, `photo_product_id`, `fraud_verdict`,
`fraud_flags JSONB`. `PRODUCTS_VERSION` gates the dataset upsert like `CATALOG_VERSION`.

**Engine** — `backend/app/integrity.py`:
- `dhash` / `hamming`; near-duplicate threshold `NEAR_DUPLICATE_BITS = 6`.
- Rule 1 (one photo, one product): compare against other listings' hashes. Different
  claimed product → `fraud`; same product → `warning`; if this post's label matches the
  photo but the other post's does not → `shared_photo` warning for the honest one.
- Rule 2 (label must match): nearest dataset product within the threshold, then compare
  claimed brand/model; a conflict yields `photo_mismatch` with the product the photo shows.
- `scan_listings()` runs at startup and persists results; `is_fraud()` keeps flagged posts
  out of `matching.rank_listings` and `recommender.legit_pool`.

**Demo posts** — l38 (Hilux photo, Tesla label → mismatch), l39 (Navara photo + Navara
label → shared_photo warning, still in the feed), l40 (Navara photo, Ford label →
duplicate + mismatch). Added in `seed_data.py`; `CATALOG_VERSION = "2026-11-03.3"`.

**API** — `GET /api/dataset/stats`, `GET /api/dataset/products`, `GET /api/integrity/flags`,
`POST /api/integrity/check` (multipart `file` or `photo=/dataset/images/<id>.jpg`).
`/dataset/*` is mounted with StaticFiles; Vite and nginx both proxy it.

**UI** — new `IntegrityTab.jsx` + nav entry: stats, the two rules, flagged posts with
badges/reasons, and a vertical-filtered dataset grid. `ListingCard` shows a red
"Photo flagged" badge when `fraud_verdict` is mismatch/duplicate.

## Live vision integrity + RL feedback loop

User asked that product identification come from live vision and that the
platform use reinforcement learning. Both are now in place.

**Live vision (`meta_client.identify_product`)** — Muse Spark receives the raw
image bytes (dataset files, uploads, or downloaded Unsplash URLs via
`integrity.load_image_bytes`) and returns brand/model/category/vertical,
confidence, visible features, and matches_claim vs the seller's claim.
Key fix: contributor models truncate structured image answers at max_tokens=500
(verified empty replies); 1500 tokens returns the full JSON. Category/vertical
vocab is normalised through a mapping (e.g. "Pickup Truck" → vehicle).

**Precedence of truth** (`effective_truth`): human correction > confident live
vision (0.5 threshold) > vision cache > dataset hash fallback > uncertain
vision (advisory warning) > unknown. `vision_source` is always reported:
live_vision / vision_cache / human / hash_fallback / unverified.

**Explore/exploit policy** (`needs_live_call`): vision is called once per
unique photo fingerprint; the verdict is cached in `vision_labels`. Re-call
only when never identified or disputes outweigh confirms. Startup scan is
local-only, no network.

**RL tables** — `vision_labels` (photo_hash PK, verdict + confirmations /
disputes / corrected fields / source) and `integrity_feedback` (every confirm
+1 / dispute −1 event with vision vs human values). `record_integrity_feedback`
promotes a corrected dispute to human ground truth; the endpoint immediately
re-runs that listing's flags, so the platform learns in one step.

**Endpoints** — `/api/integrity/check` (live vision inside, persists verdict,
force_vision flag), `/api/integrity/scan-vision?limit=` (bounded batch over
unscanned/disputed), `/api/integrity/feedback` (confirm/dispute + relearn).

**Verified live** — Hilux photo: vision says Toyota Hilux 0.96–0.97 and
rejects the Tesla claim ("Photo shows a white Toyota Hilux pickup truck, not
a Tesla Model Y SUV"); Navara photo: Nissan Navara 0.95. l38/l39/l40 all carry
vision_cache verdicts; l40 still excluded from search. Fertilizer Unsplash
photo (hands holding soil, no visible brand) correctly returns None — vision
refuses to guess, routes to Show Me. Test feedback rows were cleared after
verification; the two genuine vision verdicts remain cached.

**UI** — Integrity tab: vision-source badge per flag (green/blue/purple/grey),
"vision saw X (N%)" line, confirm/dispute buttons with correction prompt,
reward scorecard, "Run live vision" + "Re-examine disputed" buttons.

## Plates hallucination fix (user report: "need plates" → agriculture/vehicle results)

**Root cause:** "car plates" matched ITEM_KEYWORDS "car" → category vehicle →
8 vehicles ranked as the answer. The adjective hijacked the query; the wanted
noun (plates, not sold here) was ignored. Frontend also auto-navigated to
Results on any non-empty results.

**Fix — matching.py `classify_query`:** whole-word (\b) matching; UNKNOWN_NOUNS
list (plates, phones, laptops, helicopter, etc. — payment/life words like cash
and land deliberately excluded); last-noun-wins (head noun); possessive+noun
stripped as already-owned ("number plates for MY CAR" → plates, not cars);
longest-phrase-wins ("number plates" > "plates"). Model parse merge
(_parsed_from_model) cannot upgrade unknown→stocked. 11-case unit suite ALL PASS.

**Fix — chat:** unknown noun → clarification question ("vehicle number plates,
or dinner plates?") with show_results=false; honest-empty otherwise; only
show_results=true navigates (models.py + ChatTab.jsx gated). Verified live:
plates variants clarify with 0 results; fertilizer/Hilux still rank + navigate.

**Regression caught by screenshot:** first substring version matched "bag" in
"bags" and broke fertilizer queries; whole-word + exclusions fixed it. Also
fixed a self-inflicted crash: the classifier rewrite dropped parse_request_text's
return (500s) — restored with full field parsing.
